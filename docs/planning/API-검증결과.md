# 공공데이터 API 실호출 검증 결과 — 병의원·약국 (국립중앙의료원 15000736 · 15000576)

**결론부터: '지금 문 연 병원·약국'의 1순위 근거였던 데이터 조건은 실호출로 모두 확인됐고, 기대 이상이다.** 두 API 모두 요일별(월~일)·공휴일 진료시간(`dutyTime1s~8c`)과 전화번호(`dutyTel1`, 채움률 100%)를 반환하며, 공휴일 필터(`QT=8`)는 서울 전수 대조에서 누락·오탐 0건으로 정확히 동작했다. 여기에 수요 분석 리포트가 몰랐던 사실이 하나 더 있다. **위치 기반 검색 오퍼레이션은 호출 시각 기준 '지금 문 연 곳'만 거리순으로 돌려준다.** 서비스의 핵심 로직이 서버 쪽에 이미 있다는 뜻이다. 다만 세 가지 새 리스크가 드러났다. ① 응답 어디에도 기관별 수정일시가 없어 데이터 신선도는 API로 측정할 수 없다. ② 진료과목 필터는 '등록 과목 중 하나라도 해당'하는 방식이어서, 서울에서 '소아청소년과' 필터에 걸리는 3,109곳 중 이름상 소아 전문으로 보이는 곳은 15.5%뿐이다. 1차 타깃인 영유아 부모에게는 자체 분류 레이어가 필요하다. ③ 공휴일 진료시간을 등록한 서울 병의원의 55.8%가 한의원·한방병원·치과여서, "공휴일에 문 연 곳 n개"라는 숫자는 실제 쓸 수 있는 공급보다 크게 보인다. 종합하면 1순위 판단은 유지되고 실현 가능성은 '상'이 확정되지만, "데이터 보정 레이어가 차별화"라는 리포트의 결론이 이 서비스에서는 **소아 진료 가능 여부 분류**라는 구체적인 형태로 나타난다.

> 범위: 사용자 지시에 따라 이번 검증은 병의원·약국 API만 수행했다. 도서관 열람실(15142580), TAGO 버스노선(15098529), EvCharger(15076352) 검증은 별도로 진행하며, 스크립트는 준비만 해 두고 실행하지 않았다(맨 아래 '보류된 API' 참고).

## 4. 진료과목 필터(QD)와 소아 타깃 적합성

| 검증 항목 | 실측 결과 | 수요 분석 리포트 결론에 미치는 영향 |
|---|---|---|
| 코드 의미 확인 | 서울에서 이름에 '소아청소년과/소아과'가 들어간 436곳이 **전부(100%)** `QD=D002` 결과에 포함. 이비인후과 750곳 중 749곳이 `D013`, `D026` 결과의 98.6%가 치과 | D002=소아청소년과 매핑 확정. 필터의 **재현율은 완전**(소아과 의원을 놓치지 않음) |

| 다른 과목 코드 | D001(내과) 5,001 · D013(이비인후과) 2,721 · D022(가정의학과) 2,699 · D026(치과) 362. 공휴일 등록은 각각 약 10% | 성인 경증(내과·이비인후과)도 같은 문제를 가지므로, 종별+과목+이름을 조합한 자체 분류가 공통 과제 |

이름 키워드 판정은 추정치다. 실제로는 소아 전문인데 이름에 키워드가 없는 의원도 있고, 반대로 키워드가 우연히 들어간 경우도 있다. 서비스용 분류는 달빛어린이병원 목록, 종별, 진료과 등록 개수, 이름, 사용자 제보를 조합해 만들어야 한다.

| 페이지 상한 | `numOfRows=10000` 정상 동작. 1만 건 기준 병의원 7.8MB/33초, 약국 6.6MB/20초 | 전국 동기화 1회 = **병의원 8회 + 약국 3회 = 11회 호출**. 개발계정 1,000회/일로 매시간 동기화(일 264회)도 가능 → 리포트가 제시한 아키텍처가 운영계정 증량 없이 MVP 단계에서 성립 |
| FullData 필드 | 목록 API와 같은 진료시간·전화·좌표 필드에 `dutyInf`·`dutyMapimg` 포함 | 자체 '지금 영업 중' 계산(3장의 약국 버그 회피)에 필요한 데이터가 모두 있음 |

## 수요 분석 리포트 결론에 미치는 영향 — 종합

1. **1순위 유지, 실현 가능성 '상' 확정.** 리포트가 가정했던 공휴일 필터·FullData·전화번호가 모두 실측으로 확인됐고, 위치 검색의 '지금 문 연 곳' 필터라는 추가 자산이 있다. 착수 전 검증 과제 ①은 해소됐다.
2. **'데이터 한계를 전화 확인 UX로 흡수한다'는 설계가 수치로 정당화된다.** 일요일·공휴일 진료시간 등록률이 병의원 9%·약국 26%로 가장 얇고, 수정일시 필드가 없어 신선도도 알 수 없다. 가장 필요한 순간의 데이터가 가장 불확실하다.
3. **차별화 포인트가 구체화된다: '소아 진료 가능' 분류 레이어.** QD 필터의 정밀도가 15.5%여서, 영유아 부모 타깃은 공식 데이터를 그대로 보여주는 것만으로는 E-Gen과 차별화되지 않는다. 달빛어린이병원 목록 + 자체 분류 + 사용자 제보가 리포트 Conclusion의 "보정 레이어가 유일하게 복제하기 어려운 자산"에 해당하는 구체적인 형태다.
4. **"공휴일에 문 연 곳 n개"를 마케팅 지표로 쓰면 안 된다.** 서울 공휴일 공급의 55.8%가 한의원·한방·치과다. 기본 화면은 종별·과목 필터를 켠 상태여야 하고, 성과 지표는 '필요한 진료과의 영업 중 기관을 찾은 비율'처럼 정의해야 한다.
5. **아키텍처: 서버 필터를 참고하되 판정은 자체 계산.** 위치 검색은 데모·검증용으로 좋지만, 자정을 넘기는 약국을 놓치는 버그가 있고 호출 한도도 클라이언트 직접 호출을 허용하지 않는다. FullData 일일(또는 매시) 동기화 + 자체 '영업 중' 판정 + 두 가지 자정 넘김 표기 처리가 정답이다.

## 미검증 항목과 다음 검증

- **실제 공휴일 동작:** 이번 검증일은 평일(금)이다. ① 공휴일 당일 위치 검색이 `dutyTime8`을 쓰는지 ② 명절 당번 병의원·약국이 반영되는지(공휴일 전후로 `QT=8` 건수가 변하는지)는 다음 공휴일(2026-12-25)과 2027년 설 연휴에 `verify-hospital-pharmacy-opennow.ps1`과 `-deep.ps1`을 다시 돌려 확인해야 한다.
- **데이터 신선도·오류율(과제 ②):** API에 수정일시가 없으므로 FullData를 매일 스냅샷해 기관별 변경률을 쌓고, 심야·휴일 영업으로 등록된 기관 20~30곳에 표본 전화로 실제 영업 여부를 대조하는 방식이 필요하다.
- **E-Gen 등 경쟁 앱 비교(과제 ③~⑦):** API 검증 범위가 아니므로 이번에 다루지 않았다.
