## 1. 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | **지금문연** · `munyeon.kr` (2026-10-18 확정, D11) |
| 한 줄 정의 | 야간·휴일·명절에 **지금 영업 중인 병원·약국을 3초 안에 찾고, 한 번의 탭으로 전화 확인**까지 끝내며, **그 확인 결과를 다음 사람에게 남기는** 서비스 |
| 핵심 원칙 | **"3초 룰"** — 첫 화면 진입부터 전화 버튼까지 3탭·3초 이내. 탐색이 아니라 해결이 목적 |
| 핵심 루프 | **전화 → 1탭 확인 → "○분 전 통화로 확인됨"**. 전화 버튼은 출구이면서 데이터를 고치는 센서다. 원탭 전화 자체는 지도 앱에도 있으므로, 차별점은 통화 결과를 데이터로 되돌리는 이 루프다 |
| 형태 | **SEO 반응형 웹 우선**(Next.js) → 앱은 2027년 설 연휴 지표 게이트 통과 시 **React Native(Expo)**로 개발 |
| 데이터 | 국립중앙의료원 전국 병의원 찾기(15000736)·전국 약국 정보 조회(15000576) API + 자체 보정 레이어 |

**왜 웹 우선인가.** 이 서비스의 수요는 "일요일 밤 아이가 열나는 순간", "설 연휴 혈압약이 떨어진 순간"에 폭발하는 스파이크형이고, 그 순간 사용자는 앱 설치가 아니라 **검색**을 한다("추석 문 여는 약국"). SEO 최적화된 웹이 이 트래픽을 설치 장벽 없이 흡수하고, 재방문 가치가 검증된 후 앱으로 리텐션을 쌓는 순서가 스파이크형 수요 구조에 맞는다. 응급똑똑은 2025년 추석 직전 정부 안내문자로 설치를 유도했다가 접속 장애로 첫 경험이 깨졌다(리뷰 27건). 국내 검색은 네이버가 64.28%(2026년 상반기), 구글이 약 30%(2025년)라 두 곳 모두 최적화한다. 앱은 고객을 데려오는 채널이 아니라 알림·위젯·즐겨찾기로 붙잡는 장치이므로, 설 연휴 실측 지표로 착수를 결정한다(§8). 상세 근거는 [검토 문서](검토-웹우선-앱프레임워크.md).

## 2. 문제 정의와 기회 (수요 분석 요약)

- 응급실 내원의 절반가량이 경증이다(2023년 51.8%). 2024년 경증 응급실 본인부담 90% 인상 직후 명절 경증 내원이 30~44% 줄었지만, **2026년 추석에도 응급실 내원은 평소 주말보다 45% 많았고 그 51.3%가 경증**이었다. 정책만으로는 경증 수요가 응급실 밖으로 충분히 옮겨가지 않는다.
- 공휴일 진료시간을 등록한 병의원은 전국의 10.6%, 일요일은 7.5%뿐이고, 서울 공휴일 등록 병의원의 55.8%는 한의원·한방병원·치과다(2026-10 API 실측). 달빛어린이병원은 전국 156곳뿐이다(경기도 이용 건수 2025년 +23%).
- 2024년 연구에서 달빛어린이병원이 있는 지역은 경증 소아의 응급실 이용이 약 55% 수준이었다. 문 연 소아 진료기관을 **알고 갈 수 있으면** 수요가 외래로 옮겨간다는 뜻이다.
- 공식 앱은 2종이다. E-Gen은 앱스토어 평점 2.6/5(평가 125개)로 UX 격차가 여전하다. 2025년 추석부터 정부가 연휴마다 안내하는 신규 '응급똑똑'은 앱스토어 4.0/5(평가 26개)지만 **구글플레이는 2.8/5(리뷰 66개), 다운로드 5만+**로, 정부가 안전안내문자까지 보냈는데도 확산이 작다. 증상 판단이 먼저인 구조다.
- 응급똑똑 리뷰 54건(2026-10-18 수집)을 보면 불만의 성격이 바뀌었다. **2025년 추석에는 접속 장애**(27건, 안내문자 발송 직후 몰림)가, **2026년 추석에는 "진료 중으로 떠서 갔는데 닫혀 있었다"**(정보 불일치 6건 중 4건이 2026-09, 공감 수 최다)가 주된 불만이다. 오류 신고 버튼을 달아 달라는 요청도 있었다. 공식 앱의 남은 약점은 화면이 아니라 **데이터 신뢰도**이고, 개발사 답글은 0건이다.
- 데이터의 공식 한계(정부 안내문: "문 여는 병·의원에 방문하려면 먼저 해당 병·의원에 전화해 확인해야 한다")가 오히려 **원탭 전화라는 핵심 설계를 정당화**한다.

### 핵심 시나리오 (해피 패스)

1. "일요일 밤 소아과" 검색 or 앱 진입 → 위치 허용
2. 첫 화면: **지금 영업 중**인 곳만, 가까운 순 카드 리스트 (기관명·과목·마감까지 남은 시간·거리)
3. 카드의 **[전화]** 탭 → 통화로 영업·접수 가능 확인 → **[길찾기]** 탭(네이버/카카오/티맵 딥링크)
4. 통화 종료 후 복귀 시 1탭 질문: "진료 중 / 휴진 / 안 받음" → 그 카드에 **"○분 전 통화로 확인됨"**이 바로 붙고, 다음 사용자의 리스트 순서에 반영된다

## 4. 가치 제안과 차별화

| 경쟁자 | 그들의 초점 | 우리의 차별화 |
|---|---|---|
| E-Gen(공식 앱) | 동일 데이터, 기능 백화점(응급실 병상·AED·응급처치…) | **단일 과업 최적화**: 첫 화면 = 지금 문 연 곳 + 전화. 평점 2.6(2026-10)이 보여주는 UX 격차 공략 |
| 응급똑똑(공식 앱, 신규) | 증상 입력 → 중증도 분류 → 의료기관 안내. 연휴마다 정부 공식 안내 채널. 추천 리스트에 전화 버튼이 없고(상세 진입 필요, 스크린샷 기준), 오류 신고 기능이 없다 | 증상 판단 없이 **바로 '지금 연 곳 + 전화'**. 등록 진료시간을 그대로 보여주는 대신 **통화 후 확인 루프**(리뷰의 1순위 불만이자 요청 기능)와 소아 분류로 보정. 설치 없는 웹 검색 유입 |
| 네이버지도·카카오맵 | 평시 영업시간 표시 | **공휴일·명절 당직 정보**(복지부-지자체 상호검증 데이터)는 지도 앱에 없거나 부정확. "지금 영업 중만 보기"가 기본값 |
| 굿닥·똑닥 | 예약·접수·비대면진료(제휴 병원 한정) | 제휴 무관 **전국 전 기관 커버**(공공데이터), 예약이 아닌 "지금 당장" 과업 |
| 휴일지킴이약국 웹 | 약국만, 웹 조회 | 병원+약국 통합, 모바일 UX, 전화 동선 |

**방어 자산(복제가 어려운 것):** ① 전화 후 확인 응답으로 쌓이는 **실제 영업 여부 보정 데이터**(시간이 자산 — 그래서 출시 첫날부터 쌓이도록 MVP에 넣는다) ② **소아 진료 가능 여부 분류**(공식 소아과 필터 정밀도 15.5% — API 검증) ③ "명절·심야 = 이 서비스"라는 순간 점유 브랜드 ④ 연휴 검색 SEO 누적. 정부가 연휴마다 응급똑똑을 홍보하므로 ③은 정면 경쟁보다 ④(검색 유입)로 우회하는 편이 현실적이다. 오류 신고 버튼 같은 기능은 공식 앱도 금방 추가할 수 있으므로, 방어는 기능이 아니라 ①의 누적량과 반영 속도(통화 직후 바로 표시)에 둔다.

## 5. 기능 정의 (MoSCoW)

### MVP (Must — 첫 출시 범위)

| 기능 | 설명 |
|---|---|
| 지금 영업 중 필터(기본값) | 현재 시각·요일·공휴일 기준으로 영업 중인 곳만 노출. 토글로 "곧 여는 곳" 확인. 공휴일 공급의 절반 이상이 한의원·치과이므로 기본 화면은 종별·과목 필터를 켠 상태로 시작 |
| 병원/약국 토글 + 과목 필터 | 소아청소년과·내과·이비인후과 등. 공식 과목 필터는 '등록 과목 중 하나라도' 방식이라 정밀도가 낮으므로(서울 소아과 필터 15.5%), **소아 진료 가능 여부는 자체 분류로 판정**(§6). **달빛어린이병원 뱃지·필터** |
| 카드 리스트 + 지도 뷰 | 가까운 순. 카드에 마감까지 남은 시간("2시간 후 마감"), 거리, 과목 표시 |
| **원탭 전화** | 카드에서 바로 `tel:` 연결. 상세 진입 불필요. 119 연결은 오터치 방지를 위해 확인 단계를 둔 별도 영역에 둔다 |
| **통화 후 확인 루프** (v1.1에서 이동) | 통화 후 복귀하면 1탭 질문("진료 중 / 휴진 / 안 받음"). 웹에서는 `tel:` 탭 후 페이지가 다시 보이는 시점(`visibilitychange`)에 띄운다. 응답 즉시 카드에 "○분 전 통화로 확인됨" 배지, 휴진 응답이 쌓이면 경고 후 하단으로 강등(삭제 아님 — 오응답 방어). 카드마다 별도 휴진 제보 버튼. 정보 상태를 '등록 기준 / 정보 없음 / 통화로 확인됨' 셋으로 구분해 보여준다. 응답은 확인 시각·기관 단위로만 저장하고 개인 식별 정보는 받지 않는다 |
| 확인 데이터 초기 확보 | 출시 직후와 명절 전날, 운영팀이 수요 밀집 지역의 당번 약국·소아 진료기관에 표본 전화를 돌려 첫 '확인됨' 데이터를 채운다(사용자 응답이 쌓이기 전 콜드 스타트 대응) |
| 길찾기 딥링크 | 네이버지도/카카오맵/티맵 앱으로 연결 |

**인프라(2026-10-18 확정, D12~D15):** 초기 비용 최소화를 위해 월 0원으로 시작한다. 웹 Vercel Hobby, DB Supabase Free(서울 리전, PostGIS), 수집 워커 GitHub Actions 매시간 스케줄(공개 저장소). 수익·B2G가 생기면 Vercel Pro, 일시정지·용량·설 대비 시점에 Supabase Pro, 해외 러너에서 공공 API가 막히면 국내 무료 VM으로 워커를 옮긴다. 이용 분석은 자체 이벤트 테이블(전화 탭·확인 응답) + GA4.

코드 저장소는 모노레포로 시작해 앱 단계에서 로직을 그대로 가져간다: `apps/web`(Next.js), `apps/mobile`(Expo, 앱 단계에 추가), `packages/core`(공통 타입, API 클라이언트, 영업 상태 표시 규칙, 확인 루프 상태 로직), `packages/ui-tokens`(색·글자 크기·간격, 큰 글씨 모드 포함).

- 클라이언트는 공공 API를 직접 호출하지 않음(한도·키 노출 문제). 공공 API는 수집 워커만 사용.
- **명절 피크 대비:** 응급똑똑은 2025년 추석 안내문자 발송 직후 접속 장애로 리뷰 27건이 몰렸다. '지금 영업 중' 리스트는 지역 격자 × 10분 단위로 미리 계산해 CDN에 캐시하고, 확인 배지만 별도 경량 API로 덧씌운다. 연휴 전 부하 테스트는 하루 방문이 안내문자·기사 직후 1시간에 몰리는 상황을 기준으로 하고, 목표 일 UV의 3배로 여유를 둔다.
- 운영계정 트래픽 증량은 활용사례 등록 후 신청 — 출시 직후 등록을 로드맵에 포함.
- 영업 판정 로직이 제품의 심장: `공표 진료시간 → 공휴일 오버라이드(요일코드 8) → 명절 당직 정보 → 사용자 제보 오버라이드` 순의 우선순위 체인. 자정을 넘기는 영업의 두 가지 표기(`0900-2500`형과 `2000-0300`형)를 모두 처리해야 한다(공식 위치 검색 API는 후자를 놓친다). 요일 필드가 비어 있으면 '휴무'가 아니라 '정보 없음'으로 표시한다.
- **소아 진료 분류 레이어:** 공식 '소아청소년과' 필터는 등록 과목 중 하나라도 해당하면 걸리는 방식이라 서울 기준 정밀도가 15.5%다. 달빛어린이병원 목록 + 종별 + 이름 키워드 + 등록 과목 수 + 사용자 제보로 '소아 진료 가능' 여부를 자체 판정한다. P1 타깃의 핵심 기능이자 공식 앱과의 차별화 지점이다.

### 데이터 품질 전략 (최대 리스크 대응)

1. **전화 확인을 UX의 중심에**: "정보가 틀릴 수 있으니 전화로 확인하세요"를 한계가 아닌 기능으로 — 전화 버튼이 주 CTA.
2. **신선도 표기**: 모든 카드에 데이터 기준 시점, 사용자 확인 누적 시 "○분 전 확인됨" 뱃지.
3. **제보 반영**: 임시휴진 신고 n건 이상 → 리스트에서 경고 처리(삭제가 아닌 강등 — 오신고 방어).
4. **콜드 스타트**: 사용자 응답이 적은 출시 초기와 명절 전날에는 운영팀 표본 전화로 확인 데이터를 먼저 채운다. 응답률을 올리려고 질문은 1탭으로 끝내고, 응답 직후 "방금 확인이 다음 분께 표시됩니다"로 기여를 보여준다.

### SEO 설계

**노릴 곳은 롱테일이다.** "약국", "문 여는 병원" 같은 큰 검색어는 네이버 지도·플레이스와 공식 채널이 상단을 차지할 가능성이 높다(2026년 네이버 검색 결과 화면은 §11에서 직접 확인). 지역 × 과목 × 시간 조합("영통구 일요일 소아과")과 기관명 + 시간("○○약국 일요일 영업")을 페이지 체계로 덮는다.

| 페이지 | 규모 | 노리는 검색어 | 고유 가치(얇은 페이지 방지) |
|---|---|---|---|
| 기관 상세 | 병의원 79,006 + 약국 25,435 ≈ 10.4만 | "○○약국 일요일", "○○소아과 공휴일" | 요일별·공휴일 진료시간표, 원탭 전화, 통화 확인 이력, 근처 대안 기관 |
| 지역 랜딩 | 시군구 약 250 × 유형(약국·소아과·내과·이비인후과…) × 상황(일요일·공휴일·야간) | "영통구 일요일 소아과" | 그 지역·시간대의 운영 기관 목록, 등록률·확인 현황 |
| 연휴 특집 | 설·추석·성탄·신정 × 시도·시군구 | "설날 문 여는 약국 마포" | 복지부 지정 당번 정보 + 통화 확인 결과 |
| 가이드 | 수십 편 | "아이 열 39도 밤", "상비약" | 평시 유입, v2 리텐션 콘텐츠와 겸용 |

**기술 원칙**

1. **정적 정보는 서버에서, 현재 상태는 브라우저에서.** 진료시간표·공휴일 진료 여부·전화번호는 서버에서 HTML로 만들어(주기적 재생성) 검색 로봇이 읽게 한다. "지금 영업 중" 배지는 캐시된 HTML에 넣으면 시간이 지나 틀린 상태가 되므로, 브라우저에서 현재 시각으로 계산하거나 경량 API로 덧씌운다.
2. **구조화 데이터:** schema.org `Pharmacy`·`MedicalClinic`, `openingHoursSpecification`(요일별), `specialOpeningHoursSpecification`(연휴), `telephone`.
3. **얇은 페이지 관리:** 진료시간 정보가 비어 있는 기관 페이지는 `noindex`로 시작하고, 확인 데이터가 쌓이면 연다. 구글은 대량 생성된 저품질 페이지를 스팸 정책(scaled content abuse)으로 다루므로 페이지 수보다 페이지마다의 고유 정보가 중요하다.
4. **네이버:** 서치어드바이저 등록, 사이트맵 제출(10만+ URL은 파일 분할), `lastmod` 관리. 네이버 검색 로봇의 자바스크립트 실행 범위는 공식 확인이 안 됐으므로 본문은 반드시 서버 렌더링 HTML에 넣는다. 블로그·카페 시딩을 병행한다.
5. **구글:** Search Console, 사이트맵, Core Web Vitals. 모바일 첫 화면 로딩은 3초 룰과 같은 기준.
6. **색인 시간 확보:** 새 도메인은 색인과 순위가 잡히는 데 수 주에서 수 개월이 걸린다. 그래서 검색용 페이지를 인터랙션 기능보다 먼저 11월 중순에 공개한다(§8).

### 앱 게이트 (2027년 3월 판단)

| 지표 | 의미 | 초기 기준 (가설 — 소프트 런칭 실측 후 보정) |
|---|---|---|
| 연휴가 아닌 기간의 30일 재방문율 | 평시에도 다시 오는가 | 15% 이상 |
| "앱 알림 받기" 대기 신청률 | 버튼만 두고 수요를 재는 가짜 문 테스트 | 연휴 방문자의 3% 이상 |
| PWA 웹 푸시 수락률, 즐겨찾기 사용률 | 알림·즐겨찾기를 실제로 원하는가 | 추세로 판단 |

통과하지 못하면 앱 대신 웹 리텐션(PWA 알림, 카카오톡 채널 알림)에 투자하고, 2027년 추석 실측으로 다시 판단한다.

마케팅은 광고비 없이: ① 검색 SEO(§6 페이지 체계, 연휴 특집) ② 맘카페·지역 커뮤니티·네이버 블로그(P1 타깃 밀집, 네이버 검색 영역 보완) ③ 공유하기 바이럴(가족 단톡방) ④ 공공데이터 활용 공모전 출품(인지도+운영계정 증량 명분).

## 9. KPI

- **북극성 지표: 주간 전화 연결 수** (`tel:` 탭) — "찾았고, 확인했다"는 핵심 가치의 직접 측정치
- 가드레일·보조 지표:
  - 진입→전화 전환율 ≥ 25% (3초 룰 작동 검증)
  - 진입→전화까지 중앙값 시간 ≤ 15초
  - 통화 후 "영업 중이었다" 응답률 ≥ 85% (데이터 신뢰도 — 이 수치가 떨어지면 보정 레이어 최우선)
  - 통화 후 확인 응답률(전화 탭 대비 1탭 응답 비율) ≥ 30% (확인 루프가 돌아가는지 — 소프트 런칭에서 첫 실측 후 목표 보정)
  - 연휴 기간 상위 노출 카드 중 '통화로 확인됨' 비율 (보정 자산이 실제 화면에 닿는 정도)
  - 연휴 일 UV / 평시 일 UV 비율 (스파이크 의존도 추적), v2 이후 평시 재방문율
  - 제보 건수(보정 자산 축적 속도)
- **SEO 지표** (Phase 1a 공개 직후부터):
  - 색인된 페이지 수(네이버 서치어드바이저·구글 Search Console 각각) — 설 연휴 전 기관 상세·지역 랜딩의 과반 색인이 목표
  - 유입 중 자연 검색 비중(네이버·구글 구분), 연휴 기간 목표 50% 이상(가설)
  - 롱테일 검색어 노출·클릭 수, 연휴 특집 페이지의 주요 검색어 순위
  - 검색 유입 → 전화 전환율 (검색으로 온 사람도 3초 룰이 작동하는가)
- **앱 게이트 지표**: 평시 30일 재방문율, "앱 알림 받기" 대기 신청률, PWA 웹 푸시 수락률(§8)

| 확인 루프 콜드 스타트 | 높음/높음 | 출시 초기에는 응답이 적어 '확인됨' 배지가 거의 안 붙는다. 운영팀 표본 전화로 초기 데이터 확보, 1탭 응답 설계, 응답 직후 기여 표시. 응답률 KPI(≥30%)로 감시 |
| 명절 피크 접속 장애 | 중/치명 | 응급똑똑 2025 추석 사례(리뷰 27건). 리스트 사전 계산 + CDN 캐시, 연휴 전 부하 테스트(§6) |
| 새 도메인 색인 지연, 포털 자체 영역의 상단 잠식 | 높음/높음 | 설까지 16주. 검색 페이지 11월 중순 선공개, 큰 키워드 대신 롱테일 페이지 체계, 네이버 블로그·카페 시딩과 공유 링크로 검색 외 유입 확보. 색인 페이지 수 KPI로 주간 점검 |
| 지도 앱의 공휴일 정보 강화 | 중/중 | 당직 데이터+보정 데이터의 깊이로 방어, 단일 과업 브랜드 선점 |

## 11. 착수 전 검증 과제 (Phase 0 체크리스트)

3. 응급똑똑 단말 테스트: 상세 화면의 전화 기능 유무, '진료 중' 판정 로직(리뷰상 불일치의 원인), 지금 연 곳·전화까지의 탭 수, 소아 필터 품질
4. 네이버 데이터랩: "설날 약국", "일요일 소아과" 등 검색량 시계열 → UV 목표 보정
5. 리뷰 분석 — 응급똑똑은 **2026-10-18 완료**(54건, §4 표로 역산). E-Gen 리뷰는 남음
6. 상표·도메인 검색(**도메인은 10월 말까지 확정** — 11월 중순 SEO 선공개의 전제), 의료광고법상 "병원 정보 제공 서비스" 법률 검토(순위 표시·수익화 범위)
