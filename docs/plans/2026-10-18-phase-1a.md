# Phase 1a (SEO 페이지 선공개) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> 개정: 2026-10-18 — [기능 정의서](../specs/2026-10-18-mvp-features.md)와 [구조 설계·UI/UX 계획](../specs/2026-10-18-architecture-ux.md)(D16~D29)에 맞춰 Task 9 이후를 다시 짰다. Task 1~8은 완료됐고, 실제 구현에서 바뀐 이름을 반영했다.

**Goal:** 전국 병·의원 79,006곳과 약국 25,435곳의 기관 상세 페이지, 지역(시도·시군구·랜딩) 페이지, 통합 검색이 있는 홈을 `munyeon.kr`에 공개한다. 데이터는 매시간 자동 동기화하고, 분할 사이트맵을 네이버·구글에 제출한다. 목표 공개일은 2026-11-20 전후다.

**Architecture:** npm workspaces 모노레포.
- `packages/core`: 순수 TypeScript, 서버·브라우저 공용. 영업 판정, 진료시간·주소·전화 해석, 기관 분류·진료과 배지.
- `packages/db`: Postgres 쿼리, SQL 마이그레이션.
- `apps/worker`: GitHub Actions에서 매시간 FullData를 받아 Supabase에 바뀐 행만 upsert.
- `apps/web`: Next.js App Router(Vercel Hobby, icn1).

정적 정보는 CDN에 캐시한 HTML로 내보내고, 현재 상태는 브라우저에서 `packages/core`로 계산한다.

**Tech Stack:** Node 24, npm 11 workspaces, TypeScript 5.9 (strict), Vitest 4, Next.js 16(App Router) + React 19, `postgres`(porsager), `fast-xml-parser`, PGlite + PostGIS(테스트 DB), Supabase Postgres + PostGIS + `pg_trgm`, GitHub Actions, GA4(`@next/third-parties`).

**Spec:** [MVP 기능 정의서](../specs/2026-10-18-mvp-features.md), [구조 설계·UI/UX 계획](../specs/2026-10-18-architecture-ux.md), [API 검증 결과](../planning/API-검증결과.md), [DECISIONS](../DECISIONS.md), [CLAUDE.md](../../CLAUDE.md)

## Global Constraints

- 공공데이터포털 키는 `process.env.DATA_GO_KR_KEY`로만 읽는다. URL·로그·에러·fixture·커밋 어디에도 남기지 않는다(`redactKey`로 가린다).
- 공공 API는 `apps/worker`만 호출한다. 웹과 브라우저는 우리 DB·우리 API만 쓴다.
- 영업 판정: 공표 시간 → 공휴일 코드 8. 자정 넘김 두 표기를 처리하고, 전날 구간은 전날 요일코드로 판정한다. 필드가 없으면 '정보 없음'이다. 공휴일인데 코드 8이 없으면 '정보 없음'이다. 시각은 항상 KST(UTC+9)다.
- "영업 중" 같은 현재 상태는 서버 HTML·캐시된 JSON에 넣지 않는다. 클라이언트 컴포넌트가 마운트된 뒤에만 렌더한다.
- 이벤트·응답 테이블에는 기관 ID, 종류, 페이지 종류, 분 단위 시각만 저장한다. IP·UA·쿠키·좌표·검색어는 저장하지 않는다. GA4에 좌표·동네·검색어를 보내지 않는다.
- 119 전화 버튼은 두지 않는다. 링크 없는 문구 "의식이 흐리거나 숨쉬기 어려우면 바로 119에 연락하세요."만 둔다.
- 기관 노출 순서는 거리·이름순이고 금전이 개입하지 않는다.
- 모든 기관 정보 옆에 "등록된 정보가 실제와 다를 수 있어요. 방문 전 꼭 전화로 확인하세요."와 "데이터 기준: YYYY-MM-DD HH:mm"(마지막 성공 동기화)을 표시한다. '영업 중' 뒤에는 "(등록 기준)"을 붙인다.
- 지역 경로는 한글(`/서울특별시/강남구/약국/일요일`), 기관 상세는 `/pharmacy/{ID}`, `/hospital/{ID}`다.
- 반응형 폭 기준: 휴대폰 ~767px, 태블릿 768~1023px, PC 1024px~(D29).
- 성능 예산: 기관 상세 HTML 30KB 이하, 첫 화면 JS 100KB 이하(압축 후), 시스템 글꼴, 이미지 없음.
- 월 0원 구성(D12): Vercel Hobby, Supabase Free, GitHub Actions 공개 저장소.
- UI 문구·문서는 한국어, 코드 식별자는 영어.
