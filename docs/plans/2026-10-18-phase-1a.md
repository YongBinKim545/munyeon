# Phase 1a (SEO 페이지 선공개) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 전국 병·의원 79,006곳과 약국 25,435곳의 진료시간표 페이지와 지역 랜딩 페이지를 `munyeon.kr`에 공개한다. 데이터는 매시간 자동 동기화하고, 사이트맵을 네이버·구글에 제출한다. 목표 공개일은 2026-11-20 전후다.

**Architecture:** npm workspaces 모노레포. `packages/core`는 순수 TypeScript로 영업 판정, 진료시간 파싱, 지역·전화번호 정규화를 맡는다. `packages/db`는 Postgres 접근과 SQL 마이그레이션, `apps/worker`는 GitHub Actions에서 매시간 FullData를 받아 Supabase에 upsert하는 CLI, `apps/web`은 Next.js App Router(Vercel Hobby, 서울 icn1)다. 정적 정보(진료시간표·전화)는 ISR HTML로 내보내고, "지금 영업 중"은 브라우저에서 `packages/core`로 계산한다.

**Tech Stack:** Node 24, npm 11 workspaces, TypeScript 5 (strict), Vitest, Next.js(App Router, `create-next-app@latest`) + React 19, `postgres`(porsager) 드라이버, `fast-xml-parser`, `tsx`, Supabase Postgres + PostGIS, GitHub Actions, GA4(`@next/third-parties`).

**Spec:** [세부계획 §5·§6·§8](../planning/세부계획-병원약국.md), [API 검증 결과](../planning/API-검증결과.md), [DECISIONS D1~D15](../DECISIONS.md), [CLAUDE.md](../../CLAUDE.md)

## Global Constraints

- 공공데이터포털 키는 `process.env.DATA_GO_KR_KEY`로만 읽는다. URL·로그·에러 메시지·fixture·커밋 어디에도 키를 남기지 않는다. 에러에 URL을 넣을 때는 `serviceKey` 값을 `***`로 가린다.
- 공공 API는 `apps/worker`만 호출한다. `apps/web`과 브라우저는 우리 DB와 우리 API만 쓴다.
- 영업 판정 우선순위: 공표 진료시간 → 공휴일(요일코드 8) → 명절 당직(1b) → 사용자 확인(1b). Phase 1a는 앞의 두 단계만 구현하되, 체인 구조는 1b에서 단계를 추가할 수 있게 둔다.
- 자정 넘김은 `0900-2500`형(종료 > 2400)과 `2000-0300`형(종료 < 시작) 둘 다 처리한다. `0000-2400`은 24시간 영업이다.
- 요일 필드가 없으면 '휴무'가 아니라 **'정보 없음'**이다. 공휴일인데 `dutyTime8`이 없으면 '정보 없음'이다(평일 시간으로 대체하지 않는다).
- 시간 계산은 항상 Asia/Seoul(UTC+9, 서머타임 없음) 기준이다. 서버 시간대에 의존하지 않는다.
- "지금 영업 중" 상태 문구와 배지는 서버 HTML에 넣지 않는다. 클라이언트 컴포넌트가 마운트된 뒤에만 렌더한다.
- 이벤트 테이블에는 기관 ID, 이벤트 종류, 분 단위로 자른 시각만 저장한다. IP·쿠키·좌표는 저장하지 않는다. GA4에 좌표를 보내지 않는다.
- 119 연결은 별도 영역에 두고, 누르면 확인 단계를 한 번 거친다. 기관 노출 순서는 거리나 이름순이고 금전이 개입하지 않는다.
- 모든 기관 페이지에 "정보가 실제와 다를 수 있으니 방문 전 전화로 확인하세요"와 데이터 출처(국립중앙의료원, 공공데이터포털), 마지막 동기화 시각을 표시한다.
- UI 문구와 문서는 한국어, 코드 식별자는 영어로 쓴다.
- 월 0원 구성(D12): Vercel Hobby, Supabase Free, GitHub Actions(공개 저장소). 유료 기능에 기대지 않는다.

## Review Focus

1. **전날 밤 자정을 넘긴 영업 + 오늘이 공휴일:** 12-24(목) `2000-0300` 약국은 12-25(금, 공휴일) 01:00에 '영업 중'이어야 한다. 전날 구간은 전날의 요일코드로 판정한다 → Task 3 테스트 `spillover from previous weekday into holiday`.
2. **부분 동기화 실패:** 병의원 8페이지 중 5페이지에서 시간 초과가 나면, 이번에 못 본 기관을 비활성화하면 안 된다 → Task 7 테스트 `does not deactivate when any page failed`.
3. **포털 오류 응답(한도 초과·키 오류)이 '0건'으로 해석됨:** `OpenAPI_ServiceResponse`나 `resultCode != 00`을 빈 목록으로 받으면 전국 기관이 사라진다. 반드시 예외여야 한다 → Task 6 테스트 `throws PortalError on quota envelope`.
4. **좌표가 없거나 0인 기관:** 저장은 하되 `geom`은 NULL로 두고, 근처 기관 목록과 지역 집계에서 깨지지 않아야 한다 → Task 5 매핑 테스트와 Task 10 `nearby skips null geom`.
5. **캐시된 HTML에 영업 상태가 섞임:** 기관 상세 HTML 응답에 '영업 중'·'영업 종료'·'곧 마감' 문자열이 없어야 한다 → Task 10 테스트 `server HTML has no live status`.

- Create: `docs/runbook/deploy.md`(아래 체크리스트와 롤백·키 교체 절차)
