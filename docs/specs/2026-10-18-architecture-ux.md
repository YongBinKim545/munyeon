# 구조 설계 · UI/UX 계획 — 지금문연 MVP

> 작성: 2026-10-18 · 사용자와 질의응답으로 확정 · 짝 문서: [MVP 기능 정의서](2026-10-18-mvp-features.md) · 결정: [DECISIONS](../DECISIONS.md) D23~D28

## 1. 시스템 구성

```
                    ┌─ 매시 7분 ─ 병의원·약국 FullData (11호출) ─┐
[GitHub Actions] ───┼─ 매일 03시 ─ 특일 API (2호출)            ├─→ [Supabase Postgres + PostGIS, 서울]
   (수집 워커)       └─ 매일 03시 ─ 달빛어린이병원 목록 (1b, 1호출) ┘          │
                                                                          │ 읽기만
[브라우저] ── HTML·JSON ── [Vercel CDN 캐시] ──(캐시 없을 때만)── [Next.js, 서울 icn1]
    │                                                                     │
    └─ 이벤트·통화 후 응답(POST) ─────────────────────────────────────→ events, call_responses
```

| 구성요소 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 수집 워커 `apps/worker` | 공공 API 호출, 바뀐 기관만 DB 갱신, 동기화 기록, 바뀐 기관 페이지 갱신 요청 | 화면용 계산 |
| DB `packages/db` | 기관·공휴일·동네·이벤트·응답 저장, 반경·지역·이름 조회 | 영업 판정 |
| 판정 라이브러리 `packages/core` | 진료시간 해석, 영업 판정, 표시 문구, 진료과 배지 판정. 서버·브라우저 공용 | DB·네트워크 접근 |
| 웹 `apps/web` | 페이지 생성(캐시), 격자 목록·검색 JSON, 이벤트 수집 API | 공공 API 호출, 좌표 수신 |

### 1.1 두 단계를 구분한다

- **데이터 수집(공공 API → DB):** 워커만 한다. 매시간(하루 264호출, 한도 1,000). 휴일 직전·당일 변경을 1시간 안에 반영하고, 한 번 실패해도 다음 시간에 복구된다.
- **페이지 캐시(DB → 완성된 화면을 CDN에 보관):** 공공 API와 무관하다. 서버 계산(무료 한도 CPU 월 4시간)과 속도를 위한 것이다.

### 1.2 캐시 대상

| 대상 | 캐시하는 결과물 | 다시 만드는 때 |
|---|---|---|
| 기관 상세 HTML | 진료시간표, 전화번호, 주소, 근처 기관 | 7일 경과, 또는 워커가 그 기관의 내용 변경을 감지했을 때(개별 갱신 요청) |
| 지역 랜딩 HTML | 시군구 × 유형 × 상황의 기관 목록 | 1일 경과 |
| 사이트맵 XML | URL 목록과 페이지별 마지막 수정 시각 | 1시간 경과 |
| 격자 목록 JSON (1b) | 약 5km 칸 안 기관의 이름·좌표·전화·진료시간 원본·배지 | 1시간 경과 |
| 기관 이름 검색 JSON | 검색어별 상위 10건 | 1일 경과 |
| 동네 목록 JSON | 전국 동네 이름·시군구·중심 좌표(압축 약 40~60KB) | 1일 경과 |

- 캐시된 결과물에는 '영업 중' 같은 현재 상태를 넣지 않는다. 진료시간 원본만 담고 판정은 브라우저가 한다. 그래서 오래 캐시해도 상태가 틀리지 않는다.
- 워커는 내용이 바뀐 기관 ID를 `/api/revalidate`(비밀 토큰)로 보낸다. 한 번에 500곳이 넘으면 개별 갱신을 건너뛰고 7일 만료에 맡긴다.
- 명절 피크에도 DB 조회는 격자 수(약 4천 칸) × 시간당 1회 수준이다.

### 1.3 실패 대응과 운영 알림

| 실패 | 처리 |
|---|---|
| 공공 API 장애 | 직전 데이터로 계속 서비스. 사용자 화면에 경고하지 않는다(실시간 데이터가 아님) |
| 동기화 6시간 이상 미성공 | 매시 워크플로 끝의 점검 단계가 실패해 GitHub가 관리자에게 메일 |
| DB 장애 | CDN에 있는 페이지는 계속 보인다. 새 페이지만 오류 화면 |
| 워커 실패 | GitHub 실패 메일. 연속 3회면 운영자가 확인 |
| Vercel 무료 한도 | 주 1회 사용량 확인, 80%에 가까우면 Pro 전환 검토(D13) |

페이지의 "데이터 기준: 날짜·시각" 한 줄은 정직한 표시 원칙으로 유지한다.

## 2. URL과 정보 구조

```
/                                              홈
├─ /pharmacy/{기관ID}, /hospital/{기관ID}        기관 상세 (약 10.4만)
├─ /{시도}                                      시도: 시군구 목록
│   └─ /{시도}/{시군구}                          시군구 허브: 약국·병원 × 상황 링크, 요약 수치
│       └─ /{시도}/{시군구}/{약국|병원}/{전체|일요일|공휴일|야간}   지역 랜딩 (약 2천)
│            ?동={동이름}                        동네 검색에서 들어올 때(대표 주소는 동 없는 주소)
├─ /주변?유형={약국|병원}                        내 주변 목록 (1b, 색인 제외)
├─ /holiday/…                                   연휴 특집 (2027-01)
├─ /about, /privacy, /terms
├─ /sitemap.xml → /sitemaps/{n}.xml             1만 URL씩 분할
└─ /api/events, /api/search, /api/grid/{id}, /api/revalidate   (색인 제외)
```

- **지역 경로는 한글**(D24). 예: `/서울특별시/강남구/약국/일요일`.
- 홈 → 시도 → 시군구 허브 → 지역 랜딩 → 기관 상세로 링크가 이어져, 사이트맵 없이도 모든 페이지에 3~4번 클릭 안에 닿는다.
- 기관 상세 → 소속 시군구 랜딩, 근처 기관. 경로 표시와 `BreadcrumbList` 구조화 데이터.
- `?동=` 주소는 `canonical`을 동 없는 주소로 둬 중복 색인을 막는다.

## 3. 데이터 모델 보강

**기관 테이블에 추가할 열**

| 열 | 내용 | 만드는 방법 | 단계 |
|---|---|---|---|
| `category` | 일반 진료 / 한의원·한방 / 치과 / 기타(요양·정신·조산) / 약국 | 종별(`dutyDivNam`) 분류표. 첫 동기화 후 실제 값 목록으로 확정 | 1a |
| `specialty` | 주 진료과(내과, 소아청소년과 …) 또는 NULL | 기관 이름에서 진료과 단어 판정(4.3) | 1a |
| `dong` | 동 이름 | 주소 끝 괄호에서 추출 | 1a |
| `grid_id` | 약 5km 격자 번호 | 좌표에서 계산(위도 0.045° × 경도 0.056°) | 1b |
| `moonlight` | 달빛어린이병원 여부 | 하루 1번 달빛어린이병원 목록 API(같은 국립중앙의료원) | 1b |

**새 테이블:** `neighborhoods`(동네 검색용, 동기화 끝마다 재계산, 1a), `call_responses`(통화 후 응답, 기기·IP·좌표 없음, 1b). `events`의 종류는 기능 정의서 6절을 따른다. 이름 검색을 위해 `institutions.name`에 `pg_trgm` 색인을 둔다.

**MVP에서 하지 않는 데이터 보강(D28):** 심평원 병원정보·진료과목 API(홈페이지 링크, 전문의 수 기준 진료과), 홈페이지 크롤링. 크롤링은 하지 않는다(포털 약관, 이미지형 진료시간, 유지보수). 심평원 연계는 설 연휴 뒤 다음 단계에서 검토한다.

## 4. UI/UX

### 4.1 원칙 (차분한 신뢰형)

| 원칙 | 규칙 |
|---|---|
| 전화가 주인공 | 화면마다 가장 강한 색(진한 파랑) 버튼은 [전화하기] 하나. 나머지는 테두리 버튼 |
| 한 손 조작 | 버튼 높이 48px 이상. 기관 상세는 스크롤해도 [전화하기]가 하단에 고정 |
| 상태는 색 + 글자 | 영업 중 = 초록, 정보 없음 = 회색, 공휴일 기준 = 주황, 영업 종료 = 진한 회색. 항상 글자와 함께 |
| 읽기 쉬운 글자 | 본문 16px 이상, 시간·전화번호는 굵게, 고대비. 크기는 토큰으로 관리(v1.1 큰 글씨 모드 대비) |
| 다크 모드 | 휴대폰 설정을 따른다 |
| 빠른 첫 화면 | 이미지·웹폰트 없이 시스템 글꼴. 모바일 Lighthouse 성능 80 이상 |
| 정직한 문구 | '영업 중' 뒤에 "(등록 기준)". "확실", "보장" 같은 단어를 쓰지 않는다 |

### 4.2 공통 틀

- **상단 고정 헤더:** 왼쪽 로고 '지금문연'(홈), 오른쪽 검색 아이콘(어느 페이지에서든 검색창 열기).
- 헤더 아래 경로 표시 "홈 › 시도 › 시군구 › 유형".
- 하단: 출처(국립중앙의료원 · 공공데이터포털), 개인정보처리방침, 이용약관.
- 응급 안내는 링크 없는 문구 한 줄(119 전화 버튼 없음).

### 4.3 진료과 배지

- 카드마다 **주 진료과 배지 1개**. 기관 이름에서 진료과 단어를 찾는다: 내과, 소아청소년과(소아과 포함), 이비인후과, 정형외과, 피부과, 안과, 산부인과, 비뇨의학과(비뇨기과), 가정의학과, 신경외과, 신경과, 재활의학과, 정신건강의학과, 외과, 영상의학과, 마취통증의학과.
- 진료과 단어가 없으면 종별 배지: 의원, 병원, 종합병원, 한의원, 치과, 약국.
- '소아 전문' 배지는 별도: 달빛어린이병원, 또는 이름에 소아·아동·어린이·키즈, 또는 '소아 진료 가능' 제보 2건 이상(최근 180일).
- 이름 판정 정확도는 첫 동기화 후 표본 200곳으로 확인한다.

### 4.4 화면별 구성

**홈**
1. 서비스명, 한 줄 소개 "지금 문 연 병원·약국을 찾고 전화로 확인하세요"
2. [내 주변 문 연 약국] [내 주변 문 연 병원] 큰 버튼 2개(1b부터 동작. 1a에서는 버튼 대신 검색창이 맨 위)
3. "위치는 내 휴대폰에서만 쓰고 서버로 보내지 않아요"
4. 통합 검색창 "동네 또는 병원·약국 이름" + 최근 검색(브라우저 저장)
5. 지역으로 찾기: 시도 목록

**통합 검색 (D25)**
- 결과를 '동네'와 '병원·약국' 두 묶음으로 보여준다.
- 동네: 동네 목록 JSON을 검색창을 처음 누를 때 받아 브라우저에서 즉시 찾는다. 같은 이름은 "망원동 · 서울 마포구"로 구분. 선택하면 그 시군구의 지역 랜딩(`?동=`)으로 간다.
- 병원·약국: 2글자부터, 입력을 멈추고 0.3초 뒤 `/api/search` 1회. 최대 10건. 행마다 전화 아이콘(바로 전화), 행을 누르면 상세.
- 검색어는 서버에 저장하지 않는다. 초성 검색·오타 보정은 v1.1 판단.

**기관 상세** — 기능 정의서 4.1 순서대로, 하단 고정 [전화하기].

**지역 랜딩** — 기능 정의서 4.2. `?동=`으로 들어오면 그 동 기관을 맨 위로 올리고 "역삼동 근처 먼저" 표시. 1b에서 이 페이지에 아래 목록 규칙(브라우저 계산 상태 배지, [지금 문 연 곳만] 토글, 동네 중심 거리순)을 덧붙여 실사용 화면으로 쓴다(D27).

**내 주변 목록 `/주변` (1b)** — 상단 필터 줄 없음(D26). 위에서 아래로:
1. (공휴일만) "오늘은 공휴일 · 공휴일 진료시간 기준" 띠
2. 지금 영업 중 (등록 기준)
3. (공휴일만) 공휴일 정보 없음 — 평소 이 시간 여는 곳
4. 2시간 안에 여는 곳
5. "한의원·치과도 보기 (n곳)" 한 줄(병원 목록에서만)

카드: 이름 · 거리 / 진료과 배지 · 소아 전문 배지 / 상태 문구 / [전화] [길찾기].

**통화 후 질문 시트 (1b)** — 기능 정의서 5.3. "통화해 보니 어땠나요?" [진료 중] [휴진] [안 받음], 선택 칩, "알려주신 내용은 정보를 바로잡는 데만 쓰여요. 개인정보는 받지 않아요."

### 4.5 와이어프레임 요약

1a 기관 상세·지역 랜딩·홈, 홈 기본·검색 상태, 1b 내 주변 목록·통화 후 시트는 2026-10-18 대화에서 확인받았다. 구현은 4.4의 순서와 문구를 기준으로 한다.

## 5. 성능·비용 예산

| 항목 | 예산 |
|---|---|
| 기관 상세 HTML | 30KB 이하(압축 전), 페이지 생성 CPU 50ms 이하 |
| 첫 화면 JS | 기관 상세·지역 랜딩 100KB 이하(압축 후). 검색·상태 계산 외 클라이언트 코드 최소화 |
| Vercel 무료 한도 | CPU 월 4시간, 원본 전송 10GB 안. 페이지 재생성 월 약 25만 회 이내 |
| Supabase 무료 | 500MB 안(예상 약 250MB) |
