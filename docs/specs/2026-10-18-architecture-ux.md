# 구조 설계 · UI/UX 계획 — 찾아줘 메디 MVP

> 작성: 2026-10-18 · 사용자와 질의응답으로 확정 · 짝 문서: [MVP 기능 정의서](2026-10-18-mvp-features.md) · 결정: [DECISIONS](../DECISIONS.md) D23~D35
> 갱신: 2026-10-19 — 메인이 현재 위치 목록(D31), 목록 순서와 [전체 보기](D32), 위치 검색 모달·상호 검색 페이지(D33), 위치 시작 규칙(D34), 격자 JSON을 1a로(D35). `/주변` 삭제

## 1. 시스템 구성

```
                    ┌─ 매시 7분 ─ 병의원·약국 FullData (11호출) ─┐
[GitHub Actions] ───┼─ 매일 03시 ─ 특일 API (2호출)            ├─→ [Supabase Postgres + PostGIS, 서울]
   (수집 워커)       └─ 매일 03시 ─ 달빛어린이병원 목록 (1b, 1호출) ┘          │
                                                                          │ 읽기만
[브라우저] ── HTML·JSON ── [Vercel CDN 캐시] ──(캐시 없을 때만)── [Next.js, 서울 icn1]
    │                                                                     │
    └─ 이벤트·통화 후 응답(POST) ─────────────────────────────────────→ events, call_responses
```

| 구성요소 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 수집 워커 `apps/worker` | 공공 API 호출, 바뀐 기관만 DB 갱신, 동기화 기록, 바뀐 기관 페이지 갱신 요청 | 화면용 계산 |
| DB `packages/db` | 기관·공휴일·동네·이벤트·응답 저장, 반경·지역·이름 조회 | 영업 판정 |
| 판정 라이브러리 `packages/core` | 진료시간 해석, 영업 판정, 표시 문구, 진료과 배지 판정. 서버·브라우저 공용 | DB·네트워크 접근 |
| 웹 `apps/web` | 페이지 생성(캐시), 격자 목록·검색 JSON, 이벤트 수집 API | 공공 API 호출, 좌표 수신 |

### 1.1 두 단계를 구분한다

- **데이터 수집(공공 API → DB):** 워커만 한다. 매시간(하루 264호출, 한도 1,000). 휴일 직전·당일 변경을 1시간 안에 반영하고, 한 번 실패해도 다음 시간에 복구된다.
- **페이지 캐시(DB → 완성된 화면을 CDN에 보관):** 공공 API와 무관하다. 서버 계산(무료 한도 CPU 월 4시간)과 속도를 위한 것이다.

### 1.2 캐시 대상

| 대상 | 캐시하는 결과물 | 다시 만드는 때 |
|---|---|---|
| 기관 상세 HTML | 진료시간표, 전화번호, 주소, 근처 기관 | 7일 경과, 또는 워커가 그 기관의 내용 변경을 감지했을 때(개별 갱신 요청) |
| 지역 랜딩 HTML | 시군구 × 유형 × 상황의 기관 목록 | 1일 경과 |
| 사이트맵 XML | URL 목록과 페이지별 마지막 수정 시각 | 1시간 경과 |
| 격자 목록 JSON (1a, 메인 목록) | 약 5km 칸 또는 첫 화면용 약 1km 칸 안 기관의 이름·좌표·전화·진료시간 원본·종류·배지 | 1시간 경과 |
| 상호 검색 JSON | 검색어 × 격자 번호별 상위 20건(격자 번호가 없으면 검색어별) | 1일 경과 |
| 메인 HTML | 헤더 틀·안내·시도 목록·공휴일 목록(목록과 상태는 없음, D37) | 1시간 경과 |
| 동네 목록 JSON | 전국 동네 이름·시군구·중심 좌표(위치 검색 모달을 처음 열 때 받음) | 1일 경과 |

- 구현은 Next.js 기존 ISR 방식(`revalidate`, `dynamicParams`, `revalidatePath`)을 쓰고 `cacheComponents`는 끈다(D30). 첫 요청에도 본문이 완성된 HTML로 나가야 하기 때문이다.
- 캐시된 결과물에는 '영업 중' 같은 현재 상태를 넣지 않는다. 진료시간 원본만 담고 판정은 브라우저가 한다. 그래서 오래 캐시해도 상태가 틀리지 않는다.
- 워커는 내용이 바뀐 기관 ID를 `/api/revalidate`(비밀 토큰)로 보낸다. 한 번에 500곳이 넘으면 개별 갱신을 건너뛰고 7일 만료에 맡긴다.
- 명절 피크에도 DB 조회는 격자 수(약 4천 칸) × 시간당 1회 수준이다.

### 1.3 실패 대응과 운영 알림

| 실패 | 처리 |
|---|---|
| 공공 API 장애 | 직전 데이터로 계속 서비스. 사용자 화면에 경고하지 않는다(실시간 데이터가 아님) |
| 동기화 6시간 이상 미성공 | 매시 워크플로 끝의 점검 단계가 실패해 GitHub가 관리자에게 메일 |
| DB 장애 | CDN에 있는 페이지는 계속 보인다. 새 페이지만 오류 화면 |
| 워커 실패 | GitHub 실패 메일. 연속 3회면 운영자가 확인 |
| Vercel 무료 한도 | 주 1회 사용량 확인, 80%에 가까우면 Pro 전환 검토(D13) |

페이지의 "데이터 기준: 날짜·시각" 한 줄은 정직한 표시 원칙으로 유지한다.

## 2. URL과 정보 구조

```
/                                              메인: 현재 위치 기준 목록(브라우저) + 시도 목록(서버 HTML)
├─ /pharmacy/{기관ID}, /hospital/{기관ID}        기관 상세 (약 10.4만)
├─ /{시도}                                      시도: 시군구 목록
│   └─ /{시도}/{시군구}                          시군구 허브: 약국·병원 × 상황 링크, 요약 수치
│       └─ /{시도}/{시군구}/{약국|병원}/{전체|일요일|공휴일|야간}   지역 랜딩 (약 2천)
│            ?동={동이름}                        그 동 기관을 위로(처리 코드는 유지, 위치 검색은 이제 메인으로 간다)
├─ /search?q=                                   상호 검색 (색인 제외)
├─ /holiday/…                                   연휴 특집 (2027-01)
├─ /about, /privacy, /terms
├─ /sitemap.xml → /sitemaps/{n}.xml             1만 URL씩 분할
└─ /api/events, /api/search, /api/grid/{유형}/{격자}, /api/neighborhoods, /api/meta, /api/revalidate   (색인 제외)
```

- **지역 경로는 한글**(D24). 예: `/서울특별시/강남구/약국/일요일`.
- 홈 → 시도 → 시군구 허브 → 지역 랜딩 → 기관 상세로 링크가 이어져, 사이트맵 없이도 모든 페이지에 3~4번 클릭 안에 닿는다.
- 기관 상세 → 소속 시군구 랜딩, 근처 기관. 경로 표시와 `BreadcrumbList` 구조화 데이터.
- `?동=` 주소는 `canonical`을 동 없는 주소로 둬 중복 색인을 막는다.

## 3. 데이터 모델 보강

**기관 테이블에 추가할 열**

| 열 | 내용 | 만드는 방법 | 단계 |
|---|---|---|---|
| `category` | 일반 진료 / 한의원·한방 / 치과 / 기타(요양·정신·조산) / 약국 | 종별(`dutyDivNam`) 분류표. 첫 동기화 후 실제 값 목록으로 확정 | 1a |
| `specialty` | 주 진료과(내과, 소아청소년과 …) 또는 NULL | 기관 이름에서 진료과 단어 판정(4.3) | 1a |
| `dong` | 동 이름 | 주소 끝 괄호에서 추출 | 1a |
| `grid_x`, `grid_y` | 약 5km 격자 번호 | 좌표에서 계산하는 생성 열(위도 0.045° × 경도 0.056°) + 색인 | 1a |
| `moonlight` | 달빛어린이병원 여부 | 하루 1번 달빛어린이병원 목록 API(같은 국립중앙의료원) | 1b |

**새 테이블:** `neighborhoods`(동네 검색용, 동기화 끝마다 재계산, 1a), `call_responses`(통화 후 응답, 기기·IP·좌표 없음, 1b). `events`의 종류는 기능 정의서 6절을 따른다. 이름 검색을 위해 `institutions.name`에 `pg_trgm` 색인을 둔다.

**MVP에서 하지 않는 데이터 보강(D28):** 심평원 병원정보·진료과목 API(홈페이지 링크, 전문의 수 기준 진료과), 홈페이지 크롤링. 크롤링은 하지 않는다(포털 약관, 이미지형 진료시간, 유지보수). 심평원 연계는 설 연휴 뒤 다음 단계에서 검토한다.

## 4. UI/UX

### 4.1 원칙 (차분한 신뢰형)

| 원칙 | 규칙 |
|---|---|
| 전화가 주인공 | 화면마다 가장 강한 색(진한 파랑) 버튼은 [전화하기] 하나. 나머지는 테두리 버튼 |
| 한 손 조작 | 버튼 높이 48px 이상. 기관 상세는 스크롤해도 [전화하기]가 하단에 고정 |
| 상태는 색 + 글자 | 영업 중 = 초록, 정보 없음 = 회색, 공휴일 기준 = 주황, 영업 종료 = 진한 회색. 항상 글자와 함께 |
| 읽기 쉬운 글자 | 본문 16px 이상, 시간·전화번호는 굵게, 고대비. 크기는 토큰으로 관리(v1.1 큰 글씨 모드 대비) |
| 다크 모드 | 휴대폰 설정을 따른다 |
| 빠른 첫 화면 | 이미지·웹폰트 없이 시스템 글꼴. 아이콘은 lucide-react SVG(D39, 글자색을 따름). 모바일 Lighthouse 성능 80 이상 |
| 정직한 문구 | 기관 상세의 '영업 중' 뒤에 "(등록 기준)". 메인 목록은 카드마다 붙이지 않고 목록 맨 위에 한 번 안내한다(D42). "확실", "보장" 같은 단어를 쓰지 않는다 |

### 4.2 공통 틀

- **메인 헤더(D31·D38):** 로고 줄 + 1줄 📍 지역 이름 [위치 찾기 ▾] + 2줄 [약국 ▾] [검색](유형: 약국 / 병원 / 소아과, D41). 메인에만 있다. 위에 고정하지 않고 목록과 함께 스크롤되며, 위로 올릴 때만 [↑ 맨 위로] 버튼이 뜬다(2026-10-19 사용자 결정). 동작은 기능 정의서 4.4.
- **다른 페이지 헤더:** 왼쪽 로고 '찾아줘 메디'(메인), 오른쪽 검색 아이콘(상호 검색 페이지 `/search`).
- 메인이 아닌 페이지는 헤더 아래 경로 표시 "홈 › 시도 › 시군구 › 유형".
- 하단: 출처(국립중앙의료원 · 공공데이터포털), 개인정보처리방침, 이용약관.
- 응급 안내는 링크 없는 문구 한 줄(119 전화 버튼 없음).

### 4.3 진료과 배지

- 카드마다 **주 진료과 배지 1개**. 기관 이름에서 진료과 단어를 찾는다: 내과, 소아청소년과(소아과 포함), 이비인후과, 정형외과, 피부과, 안과, 산부인과, 비뇨의학과(비뇨기과), 가정의학과, 신경외과, 신경과, 재활의학과, 정신건강의학과, 외과, 영상의학과, 마취통증의학과.
- 진료과 단어가 없으면 종별 배지: 의원, 병원, 종합병원, 한의원, 치과, 약국.
- '소아 전문' 배지는 별도: 달빛어린이병원, 또는 이름에 소아·아동·어린이·키즈, 또는 '소아 진료 가능' 제보 2건 이상(최근 180일).
- 이름 판정 정확도는 첫 동기화 후 표본 200곳으로 확인한다.

### 4.4 화면별 구성

**메인 `/` (D31·D32·D34)** — 기능 정의서 4.4. 위에서 아래로:
1. 메인 헤더(4.2)
2. (공휴일만) "오늘은 공휴일 · 공휴일 진료시간 기준" 띠
3. 목록(브라우저): 영업 중 → 곧 영업 → (공휴일) 전화 확인 필요 → [전체 보기] → (전체) 문 닫은 곳·정보 없는 곳. 병원은 각 구간 끝에 한의원·치과
4. 안내 문구 + 데이터 기준
5. 지역으로 찾기: 시도 목록(서버 HTML)

카드: 이름 · 거리 / 진료과 배지 · 소아 전문 배지 / 상태 문구 또는 배지 / [전화하기] [길찾기] 나란히.

**위치 검색 모달 (D33)** — 휴대폰은 화면 전체, 태블릿·PC는 가운데. 검색창 + 동네 결과. 동네 목록 JSON을 모달을 처음 열 때 받아 브라우저에서 즉시 찾는다. 같은 이름은 "망원동 · 서울 마포구"로 구분. 모달을 열 때 브라우저 기록에 한 칸을 넣어 휴대폰 뒤로 가기가 모달만 닫게 한다.

**상호 검색 `/search` (D33·D37)** — 검색창 + 결과 목록. 2글자부터, 입력을 멈추고 0.3초 뒤 `/api/search?q=…&g=…` 1회(`g`는 메인에서 보던 중심의 약 5km 격자 번호). 서버는 칸 중심에서 가까운 20건, 브라우저가 보던 중심 좌표로 다시 정렬하고 거리를 표시한다. 최대 20건, 행마다 전화 아이콘, 행을 누르면 상세. 검색어는 주소(`?q=`)에 남겨 뒤로 가기로 돌아와도 결과가 유지된다. 검색어는 서버에 저장하지 않는다.

**기관 상세** — 기능 정의서 4.1 순서대로, 하단 고정 [전화하기].

**지역 랜딩** — 기능 정의서 4.2. 검색 유입용 정적 목록으로 둔다(D31로 1b 확장 취소).

**통화 후 질문 시트 (1b)** — 기능 정의서 5.3. "통화해 보니 어땠나요?" [진료 중] [휴진] [안 받음], 선택 칩, "알려주신 내용은 정보를 바로잡는 데만 쓰여요. 개인정보는 받지 않아요."

### 격자 목록 받기와 범위 넓히기 (D36)

- **2단계:** 먼저 반경 1km에 걸치는 약 1km 칸(위도 0.009° × 경도 0.0112°, 9칸 안팎)을 받아 바로 그린다. 이어서 반경 3km의 약 5km 칸을 백그라운드로 받아 합친다(같은 기관은 한 번만).
- **늦게 온 기관:** 순서 규칙대로 제자리에 넣는다. 보고 있는 카드는 화면 위치가 그대로 남도록 스크롤을 보정한다(사파리는 자동 보정이 없어 코드로 한다).

- 격자 한 칸은 위도 0.045° × 경도 0.056°(약 5km). 중심이 든 칸과 이웃 8칸(3×3)을 먼저 받으면 중심에서 최소 약 5km까지 빠짐없이 들어온다.
- 3km 안에서 보여줄 곳이 5곳 미만이면 10km, 그래도 부족하면 25km로 넓힌다. 각 단계에서 반경에 조금이라도 걸치는 칸만 받는다(최대 9·25·121칸). 이미 받은 칸은 다시 받지 않는다.
- 25km 단계는 기관이 드문 지역에서만 일어나므로 칸 대부분이 비거나 작다. 칸 JSON은 CDN 캐시라 DB 조회는 칸 수 × 시간당 1회를 넘지 않는다.

### 4.5 PC·태블릿 (반응형, D29)

같은 URL·같은 HTML을 폭에 따라 배치만 바꾼다. 별도 화면은 만들지 않는다.

| 폭 | 기관 상세 | 지역 랜딩·메인 목록 | 메인 헤더·검색 |
|---|---|---|---|
| 휴대폰 (~767px) | 한 줄, 하단 고정 [전화하기] | 카드 한 줄 | 헤더 세 줄(고정하지 않음, 위로 올릴 때 [↑ 맨 위로]), 위치 검색은 화면 전체 모달 |
| 태블릿 (768~1023px) | 한 줄(최대 폭 720px, 가운데), 상단 [전화하기](하단 고정 없음) | 카드 두 줄 | 헤더 가운데 정렬, 위치 검색은 가운데 모달 |
| PC (1024px~) | 두 칸: 왼쪽 진료시간표·근처 기관, 오른쪽 전화번호·[번호 복사]·길찾기 카드(스크롤 따라옴) | 카드 세 줄 | 헤더 세 줄 가운데 정렬, 위치 검색은 가운데 모달, 시도 목록 여러 칸 |

- **전화:** 터치 기기가 아닌 PC(`pointer: fine` + `hover`)에서는 전화번호를 크게 글자로 보여주고 [번호 복사] 버튼을 둔다. `tel:` 링크도 남긴다. 번호 복사도 `tel_tap`과 구분해 `tel_copy` 이벤트로 남긴다.
- **현재 위치:** PC에서 현재 위치로 목록을 보여줄 때 지역 이름 아래에 "PC는 위치가 부정확할 수 있어요" 한 줄을 붙인다.
