# MVP 기능 정의서 — 지금문연

> 갱신: 2026-10-18 — 구조·UI/UX 설계에서 바뀐 점 반영: 통합 검색(동네 + 기관 이름), 동네 선택 시 지역 랜딩으로, 지역 랜딩을 1b 실사용 화면으로 확장, 목록 상단 필터 대신 진료과 배지, 소아 탭 대신 배지. 화면 구성은 [구조 설계·UI/UX 계획](2026-10-18-architecture-ux.md)
> 갱신: 2026-10-19 — 앱을 써 본 사용자 의견 반영(D31~D35): 메인이 곧 현재 위치 기준 목록(1a로 앞당김), 메인 전용 헤더(지역·유형·상태 드롭다운), 목록 한 줄 순서와 [전체 보기], 위치 검색(모달)과 상호 검색(페이지) 분리. `/주변` 화면과 지역 랜딩의 1b 확장은 취소
> 범위: 2027 설 연휴(2/6~9) 출시분. Phase 1a(2026-11-20 전후 공개)는 동작까지 상세히, 1b(12월 중순)는 규칙 수준까지 정한다.

## 1. 목적과 성공 기준

- **목적:** 야간·휴일·명절에 지금 문 연 병원·약국을 3초 안에 찾아 원탭으로 전화 확인한다.
- **1차 타깃:** 아이가 아픈 맞벌이 부모(P1). 1인 가구(P2), 고령 부모를 대신 찾는 자녀(P3).
- **성공 기준(세부계획 §9):** 북극성 지표는 주간 전화 연결 수. 진입→전화 전환율 25% 이상, 진입→전화 중앙값 15초 이하. 확인 응답률은 수집만 하므로 목표 대신 실측치로 본다.
- **정직한 표시 원칙:** '등록 기준'과 '정보 없음'을 구분해서 보여주고, 정보 없음을 휴무로 표시하지 않는다. 모든 기관 정보 옆에 "방문 전 전화로 확인"을 둔다.

## 2. 기능 목록과 단계

| 기능 | 단계 | 요약 |
|---|---|---|
| 기관 상세 페이지 | 1a | 진료시간표, 원탭 전화, 길찾기, 근처 기관, 지금 상태(브라우저 계산). 약 10.4만 페이지 |
| 지역 랜딩 페이지 | 1a | 시군구 × 약국/병원 × 전체·일요일·공휴일·야간 |
| 위치 검색 | 1a | 메인 지역 드롭다운 안의 모달. 동네 이름을 브라우저 안에서 찾고, 고르면 메인 목록의 중심이 바뀐다(D33) |
| 상호 검색 | 1a | 별도 페이지 `/search`. 병원·약국 이름을 우리 DB 색인으로 찾고, 보고 있는 지역에서 가까운 순(D33) |
| 메인(현재 위치 목록) | 1a | 메인 전용 헤더(지역·유형·상태) + 거리순 목록 + [전체 보기] + 서버 HTML 시도 목록(D31·D32·D35) |
| 원탭 전화 | 1a | 카드·상세에서 바로 `tel:` |
| 길찾기 딥링크 | 1a | 네이버지도·카카오맵·티맵 앱(없으면 웹). 지도 뷰는 없다 |
| 진료과·소아 배지 | 1a | 카드마다 이름 기준 주 진료과 배지 1개 + '소아 전문' 배지. 상단 필터 줄은 없다 |
| 통화 후 질문 | 1b | 1탭 응답 + 선택형 제보. **수집만 하고 실시간 표시는 보류** |
| 연휴 특집 페이지 | 2027-01 초 | 설 연휴 시도·시군구별 |

**MVP에서 하지 않는 것:** 지도 뷰, 실시간 '○분 전 확인' 배지(소프트 런칭 실측 후 결정), 자유 댓글·별점(v2 이후 계정 기능과 함께), 119 전화 버튼, 즐겨찾기·공유·큰 글씨(v1.1), 예약·비대면진료·약 재고·커뮤니티(기존 Won't).

## 3. 공통 규칙

### 3.1 영업 상태 판정

- 우선순위: 공표 진료시간 → 공휴일(요일코드 8) → 명절 당직(API 반영 여부 12-25 재검증 후) → 이용자 확인(표시 보류 중이라 MVP에서는 판정에 쓰지 않음).
- 자정 넘김 두 표기(`0900-2500`, `2000-0300`)를 모두 처리한다. 전날 시작한 구간은 전날의 요일코드로 판정한다.
- 공휴일인데 코드 8이 없으면 '정보 없음'이다. 평일 시간으로 대체해 '영업 중'이라고 하지 않는다.
- 현재 상태는 서버 HTML에 넣지 않고 브라우저에서 계산한다. 시각은 항상 한국 시간 기준이다.

### 3.2 상태 문구

| 상태 | 문구 예 |
|---|---|
| 영업 중 | "영업 중 · 오후 6시 마감 (등록 기준)", 1시간 이내면 "곧 마감 · 40분 남음" |
| 영업 전 | "영업 전 · 오전 9시 시작" |
| 영업 종료 | "영업 종료 · 내일 오전 9시 시작"(내일 정보가 있을 때) |
| 정보 없음 | "오늘 정보 없음 — 전화로 확인" |
| 공휴일 | 위 문구 앞에 "오늘은 공휴일 · 공휴일 진료시간 기준" |

### 3.3 기관 종류 구분

- 약국: 약국 API 전체.
- 병원 '일반 진료': 종별이 의원·병원·종합병원·상급종합병원·보건소 계열이고 한의원·한방병원·치과의원·치과병원이 아닌 곳.
- 한의원·치과: 데이터는 모두 수집하고 상세·지역 페이지도 만든다. 메인 병원 목록에서는 접지 않고 **각 구간의 맨 아래**에 둔다(D32). 지역 랜딩에서는 목록 끝 "한의원·치과도 보기 (n곳)" 한 줄로 접는다(4.2).
- 요양병원·정신병원·조산원: 한의원·치과와 같이 취급한다(메인은 각 구간 맨 아래, 지역 랜딩은 접힌 줄).
- 주 진료과 배지 규칙은 [구조 설계·UI/UX 계획](2026-10-18-architecture-ux.md) 4.3.

### 3.4 응급 안내

- 119 전화 버튼은 두지 않는다(오터치 원인, 119는 모두 안다).
- 기관 상세와 결과 0곳 화면에 링크 없는 안내 문구 한 줄: "의식이 흐리거나 숨쉬기 어려우면 바로 119에 연락하세요."

## 4. Phase 1a 상세

### 4.1 기관 상세 페이지 (`/pharmacy/{기관ID}`, `/hospital/{기관ID}`)

**화면 순서(모바일 한 열)**

1. 이름 · 종별 · 주소
2. 지금 상태 줄(3.2, 브라우저 계산)
3. **[전화하기]** 큰 버튼(주 동작) + [길찾기] 버튼(네이버·카카오·티맵 선택 시트)
4. "등록된 정보가 실제와 다를 수 있어요. 방문 전 꼭 전화로 확인하세요." + "데이터 기준: 2026-11-20 14:07"(마지막 성공 동기화)
5. 요일별 진료시간표: 월~일 + 공휴일. 오늘 행 강조. 빈 칸은 '정보 없음'. 자정 넘김은 "20:00~익일 03:00", 24시간은 "24시간"
6. 근처 같은 종류 기관 최대 5곳(반경 3km): 이름, 거리, 일요일·공휴일 운영 여부, [전화]
7. 응급 안내 문구(3.4)
8. 출처: 국립중앙의료원 · 공공데이터포털(공공누리 표시)

**예외**

| 상황 | 동작 |
|---|---|
| 진료시간 전부 비어 있음 | 페이지는 보여주고 `noindex`. 진료시간표 자리에 "등록된 진료시간이 없어요 — 전화로 확인" |
| 전화번호 없음·형식 오류 | 전화 버튼 대신 "전화번호 정보 없음", 근처 기관을 진료시간표 위로 올린다 |
| 좌표 없음 | 근처 기관 숨김, 길찾기는 주소 검색 링크로 |
| 동기화에서 사라진 기관 | 404 대신 "현재 운영 정보가 없습니다" + 근처 기관, `noindex`, 사이트맵 제외 |
| 없는 기관 ID | 404 + [메인으로] [상호 검색] |

**검색 노출**

- 제목: 약국 "○○약국 영업시간 · 일요일·공휴일 | 지금문연", 병원 "○○의원 진료시간 · 일요일·공휴일 | 지금문연"
- 설명: 주소 + 일요일·공휴일 시간 요약(예: "일요일 10:00~14:00, 공휴일 정보 없음")
- 구조화 데이터: schema.org `Pharmacy` / `MedicalClinic`, `openingHoursSpecification`(월~일, 정보 있는 요일만), `telephone`, `address`, `geo`
- 캐시: 하루 단위 재생성(ISR). 진료시간이 바뀌면 사이트맵 `lastmod`가 바뀐다.

### 4.2 지역 랜딩 페이지 (`/r/{시도}/{시군구}/{pharmacy|hospital}/{all|sunday|holiday|night}`)

- 제목 예: "강남구 일요일 문 여는 약국 — 영업시간·전화 | 지금문연"
- 맨 위 요약: "등록 기준 n곳 · 이 지역 공휴일 진료시간 등록률 x%"
- 목록: 이름순(위치를 모르므로). 행마다 해당 상황의 시간, [전화], 상세 링크.
- 상황 정의: 일요일 = 코드 7 있음, 공휴일 = 코드 8 있음, 야간 = 평일(월~금) 중 하루라도 22:00 이후까지 영업.
- 병원 목록은 일반 진료를 먼저 보여주고, 한의원·치과는 목록 끝 "한의원·치과도 보기 (n곳)" 한 줄로 접는다(3.3).
- 같은 시군구의 다른 상황·유형 링크, 이웃 시군구 링크.
- 해당 기관이 3곳 미만이면 `noindex`.

### 4.3 위치 검색과 상호 검색 (D33)

**위치 검색 (모달, 메인에서만)**

- 메인 지역 드롭다운 맨 위 [위치 검색]으로 연다. 휴대폰(~767px)은 화면 전체를 덮고, 태블릿·PC는 가운데 모달이다.
- 닫기: 닫기 버튼, Esc, 휴대폰 뒤로 가기. 뒤로 가기는 모달만 닫고 페이지를 떠나지 않는다.
- 입력: 읍면동 또는 시군구 이름(예: "영통동", "망원", "강남구"). 두 글자부터 브라우저 안에서 자동완성한다. 동네 목록 JSON은 모달을 처음 열 때 받는다.
- 동네 목록: 기관 주소 끝 괄호의 동 이름(예: "(역삼동)")과 시군구에서 만든다. 동네 중심 좌표는 그 동네 기관 좌표의 중앙값. 외부 주소 API를 쓰지 않는다.
- 같은 동 이름이 여러 지역에 있으면 "망원동 · 서울 마포구"처럼 시군구를 붙여 고르게 한다.
- 고르면 모달이 닫히고 메인 목록의 중심이 그 동네 중심 좌표로 바뀐다. 고른 지역은 최근 지역 맨 앞에 들어간다.

**상호 검색 (페이지 `/search`)**

- 헤더의 [검색]으로 간다(메인은 2줄 오른쪽, 다른 페이지는 로고 줄 오른쪽). `noindex`, 사이트맵 제외.
- 병원·약국 이름만 찾는다. 2글자부터, 입력을 멈추고 0.3초 뒤 1회 조회, 최대 20건.
- 정렬: 메인에서 보던 지역에서 가까운 순. 서버에는 좌표 대신 약 5km 격자 번호만 보낸다(D21). 격자 번호가 없으면(검색 페이지로 바로 들어온 경우) 이름 앞부분 일치 → 짧은 이름순.
- 행: 이름 · 진료과 배지 · 시군구 · 거리(격자 번호가 있을 때), 전화 아이콘(바로 전화). 행을 누르면 상세. 뒤로 가기로 돌아오면 검색어와 결과가 남아 있다.
- 검색어는 서버에 저장하지 않는다. 초성 검색·오타 보정은 v1.1 판단.

### 4.4 메인 `/` (1a, D31·D32·D34)

**헤더 (메인 전용)**

- 로고 줄: '지금문연'(누르면 메인).
- 1줄: [📍 마포구 망원동 ▾]. 표시는 시군구 + 동이다. 같은 이름의 시군구가 여러 시도에 있으면 '부산 중구'처럼 시도를 붙인다.
  - 현재 위치일 때 지역 이름은 가장 가까운 기관의 시군구·동으로 붙인다(외부 주소 API 없음).
  - 드롭다운 순서: [위치 검색](4.3 모달) → [현재 위치] → 최근 지역 3개(최근 고른 순).
- 2줄: [약국 ▾] [영업 중 ▾] [검색]. '유형'·'상태' 글자는 화면에 보이지 않고 화면 낭독기용 이름으로만 둔다.
  - 유형: 약국 / 병원. 처음은 약국, 이후 마지막 선택을 기억한다.
  - 상태: 영업 중 / 전체. 들어올 때마다 '영업 중'.
  - [검색]: 상호 검색 페이지(4.3).
- 스크롤: 헤더는 위에 고정하지 않고 목록과 함께 올라간다. 한 화면 이상 내려간 뒤 위로 올리면 오른쪽 아래에 [↑ 맨 위로] 버튼이 나타나고, 아래로 내릴 때는 숨는다. 목록 끝에는 버튼 높이만큼 여백을 둬 마지막 카드가 가려지지 않게 한다.
- 다른 페이지(기관 상세·지역·소개 등)의 헤더는 로고 줄 + 검색만 있다.

**위치 (D34)**

- 들어올 때마다 현재 위치로 시작한다. 첫 방문에는 브라우저가 위치 권한을 묻는다.
- 거부하거나 8초 안에 못 잡으면 최근 지역 1순위, 최근 지역이 없으면 서울 중구 명동(고정 좌표)으로 시작한다.
- 드롭다운의 [현재 위치]를 누르면 다시 위치를 잡는다. 권한이 꺼져 있으면 "위치 권한이 꺼져 있어요. 브라우저 설정에서 켜 주세요" 한 줄을 보여준다.
- 유형·최근 지역은 브라우저에만 저장한다. 좌표는 서버로 보내지 않는다(서버에는 약 5km 격자 번호만, D21).
- 휴대폰 브라우저는 `https://` 주소에서만 위치를 허용한다.

**목록 (D32)**

- 데이터: 중심 주변의 격자 목록 JSON(CDN 1시간 캐시). 거리·영업 판정·정렬은 브라우저가 한다.
- 범위: 중심에서 3km로 시작하고, '영업 중' 상태에서 보여줄 곳(아래 ①~③)이 5곳 미만이면 10km, 25km로 넓힌다. 동 경계 밖이어도 가까우면 포함한다.
- 구역 제목 없이 한 줄로, 위에서부터:
  1. **지금 영업 중(등록 기준):** 상태 문구는 3.2("영업 중 · 오후 6시 마감 (등록 기준)", "곧 마감 · 40분 남음").
  2. **곧 영업:** 지금은 닫혀 있고 2시간 안에 연다(자정을 넘겨도). 배지 '곧 영업 · 1시간 뒤 오후 9시'.
  3. **(공휴일만) 전화 확인 필요:** 오늘 공휴일 시간(코드 8)은 없지만 오늘 요일의 평소 시간으로는 지금 영업 중인 곳. 배지 '전화 확인 필요' + 문구 '평소 금요일엔 이 시간 영업'. 평소 그 요일 시간도 없는 기관은 넣지 않는다.
- 각 구간 안은 거리순이고, 병원이면 한의원·치과(요양·정신·조산 포함)는 그 구간의 맨 아래(그 안에서 거리순)에 둔다.
- 목록 끝 **[전체 보기]:** 누르면 상태 드롭다운이 '전체'로 바뀌고, 같은 범위의 나머지(문 닫은 곳, 정보 없는 곳)가 거리순으로 아래에 붙는다(한의원·치과는 맨 아래). 구분 문구는 없고, 위쪽 목록과 스크롤 위치는 그대로다. 드롭다운에서 '전체'를 고른 것과 결과가 같다. '영업 중'으로 되돌리면 ①~③만 남는다.
- ①~③이 하나도 없으면: "등록 기준으로 지금 문 연 곳이 없어요" + 응급 안내 문구(3.4) + [전체 보기].
- 공휴일이면 목록 위에 "오늘은 공휴일 · 공휴일 진료시간 기준" 띠.
- 카드: 이름 · 거리 / 진료과 배지 · 소아 전문 배지 / 상태 문구 또는 배지 / [전화하기](진한 색) [길찾기](테두리) 나란히. 이름을 누르면 상세. PC는 전화번호 + [번호 복사](D29).
- 목록 아래: "등록된 정보가 실제와 다를 수 있어요. 방문 전 꼭 전화로 확인하세요." + "데이터 기준: 날짜·시각".

**서버 HTML (검색 로봇·위치를 못 쓰는 사람용)**

- 헤더 틀, 한 줄 소개 "지금 문 연 병원·약국을 찾고 전화로 확인하세요", 지역으로 찾기(시도 → 시군구 페이지 링크), 안내 문구는 서버에서 그린다(1시간 캐시).
- 목록과 지역 이름은 브라우저에서만 그린다. 영업 상태는 HTML에 들어가지 않는다.

## 5. Phase 1b 규칙

### 5.1 지금 영업 중 리스트

1a 메인(4.4)으로 옮겼다(D31·D35). `/주변` 화면은 만들지 않는다.

### 5.2 진료과·소아 배지

- 별도 소아 탭은 두지 않는다. 소아 진료는 배지로 찾는다(D26). 이름 기준 배지는 1a, 달빛어린이병원·제보 기준은 1b.
- 주 진료과 배지: 이름 기준 1개(구조 설계 4.3). 소아청소년과 의원은 [소아청소년과] 배지가 붙는다.
- '소아 전문' 배지: 달빛어린이병원, 또는 이름에 소아·아동·어린이·키즈, 또는 최근 180일 '소아 진료 가능' 제보 2건 이상.
- 배지는 강조만 하고 정렬을 바꾸지 않는다.
- 데이터: 달빛어린이병원 목록(같은 국립중앙의료원 API)을 하루 1번 받는다. 심평원 진료과목 등 외부 데이터 보강은 MVP에서 하지 않는다(D28).

### 5.3 통화 후 질문

- 조건: [전화] 탭 후 페이지가 가려졌다가 다시 보일 때, 자리를 비운 시간이 10초 이상이면 하단 시트를 띄운다.
- 질문: "통화해 보니 어땠나요?" [진료 중] [휴진] [안 받음]. 선택 칩: 소아 진료 가능 / 공휴일에도 열었어요 / 전화번호가 달라요. 닫기 버튼이 크고, 무시해도 된다.
- 응답 후: "고맙습니다. 알려주신 내용은 정보를 바로잡는 데 쓰여요."
- 저장: 기관 ID, 응답, 칩, 분 단위 시각, 자리 비운 시간(10초 구간). 기기 식별자·IP·좌표는 저장하지 않는다.
- 중복: 같은 기관은 브라우저에서 6시간에 1번만 응답받는다.
- 활용: 소아 전문 배지(5.2), '전화번호가 달라요' 3건 이상이면 운영자 확인 목록(공공데이터포털 오류 신고로 전달), 기관별 응답 기록 축적.
- **실시간 표시 여부:** 12-25~01-01 소프트 런칭에서 응답률·지역 밀도·응답 일관성을 재고, 2027-01 중순에 설 연휴 표시 여부를 결정한다.

## 7. 개인정보·법적 고려

- 위치 좌표는 서버로 보내지 않는다(격자 번호만 요청). 위치기반서비스사업 신고 필요성을 줄이는 설계이며, 최종 판단은 법률 확인 항목으로 남긴다.
- 통화 후 응답과 제보는 개인 식별 정보 없이 저장한다.
- 자유 텍스트를 받지 않으므로 게시물 임시조치·명예훼손 대응 부담이 없다.
- 병원 노출 순서는 거리·이름순이며 금전이 개입하지 않는다.
